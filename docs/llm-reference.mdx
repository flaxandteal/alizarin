## What Alizarin Is

Alizarin is a multi-language SDK for working with [Arches](https://www.archesproject.org/) graph-based heritage data management systems. It provides tile/JSON conversion, an ORM layer with editing, graph mutation, derive (computed-tile) functions, resource-layer composition, resource lifecycles, SKOS vocabulary parsing, and reference data management. The core is written in Rust with bindings for JavaScript/TypeScript (WASM + NAPI), Python (PyO3), and direct Rust use. All three backends are kept in parity and return the same JSON, byte for byte; absent values are `null`, never `undefined`.

**Do not** write custom code to parse Arches tiles, convert between tiles and JSON trees, manipulate graph schemas, or handle SKOS vocabularies. Alizarin already does all of this.

## Installation

```bash
# JavaScript/TypeScript (browser + Node.js). 2.0 is on the npm `alpha` tag;
# a bare `npm install alizarin` gets the old 1.x line.
npm install alizarin@alpha
npm install @alizarin/napi@alpha   # optional native Node backend

# Python: pin the alpha (older 2.0.0bN betas sort above it, so --pre picks those)
pip install "alizarin==2.0.0a147"

# Rust
cargo add alizarin-core@2.0.0-alpha.147
```

## Core Concepts

- **Graph**: An Arches resource model definition. Contains nodes, nodegroups, edges, and cards. Each graph has a UUID.
- **Node**: A field in the graph. Has a datatype (string, concept, semantic, etc.), an alias, and belongs to a nodegroup.
- **Nodegroup**: A group of related nodes. Controls cardinality (1 or n). A node whose `nodeid == nodegroup_id` is a **collector** node (owns its own nodegroup).
- **Collector (is_collector)**: A node that owns its own nodegroup. In Arches, `is_collector` is the property `nodeid == nodegroup_id`. Set `options.is_collector = true` on `AddNode` to force nodegroup creation for cardinality-1 nodes.
- **Tile**: A data record for a nodegroup. Contains values keyed by node UUID.
- **Resource**: An instance of a graph. Contains tiles.
- **Alias**: A human-readable name for a node (e.g., `person_name` instead of a UUID).
- **Semantic node**: A grouping node with no data of its own. Its children hold actual values.
- **RDM**: Reference Data Manager. Handles controlled vocabulary (concept) lookups.

## JavaScript/TypeScript Patterns

### Pattern 1: Load and query resources

```typescript
import { client, graphManager, staticStore, RDM, wasmReady } from 'alizarin';

// Wait for the WASM core before initialising (the ORM runs on a Rust core).
await wasmReady;

// Client classes live under the `client` namespace, NOT the top level.
const archesClient = new client.ArchesClientRemoteStatic('/data');

// Idiomatic setup uses the exported singletons. Set the SAME client on all
// three: graphManager (schemas), staticStore (resources), RDM (concepts).
graphManager.archesClient = archesClient;
staticStore.archesClient = archesClient;
RDM.archesClient = archesClient;

// initialize() populates graph metadata; loadGraph() throws without it.
// (Do NOT `new GraphManager(client)` then loadGraph directly — that skips init.)
await graphManager.initialize();

const Person = await graphManager.loadGraph('Person');
const people = await Person.all();

for (const person of people) {
  // Property access is ASYNC — every field must be awaited.
  console.log(await person.forename);           // string value
  console.log(await person.birthDate);          // Date object
  // Concepts are String subclasses; there is NO .prefLabel.
  // Await the field, then stringify to get the label.
  console.log((await person.role)?.toString()); // concept label
}
```

`loadGraph` takes the model's class name from the graph list (`'DigitalObject'`;
case, spaces and punctuation are ignored, so `'Digital Object'` works) or a graph
id. An unknown name throws with the names it knows. For files on disk, use
`client.ArchesClientLocal`; see [Local testing](/docs/local-testing).

### Pattern 1b: Follow resource references

```typescript
// A resource-instance value is a STUB: id only, `$` and `__` null.
const site = await person.primary_site;
site.id;                                  // the referenced resource's id

// Reading any attribute retrieves it (registry first, then the client).
const siteName = await site.name;
const org = await site.maintained_by;     // a stub again
console.log(String(await org.name));

// Descriptors without retrieving, if the data carries __cache; else null.
await site.getName();                     // string | null
await site.getName(true);                 // retrieves if needed
```

The referenced resource must be in the registry (load its graph's business
data, e.g. `await Site.all()`) or fetchable by the client. See
[Resource references](/docs/resource-references).

### Pattern 2: Build a graph from CSV

```typescript
import { buildGraphFromModelCsvs } from 'alizarin';

// Signature is (graphCsv, nodesCsv, rdmNamespace, collectionsCsv?) — rdmNamespace
// comes BEFORE the optional collectionsCsv. Returns { graph, collections }.
const { graph, collections } = buildGraphFromModelCsvs(
  graphCsv, nodesCsv, rdmNamespace, collectionsCsv,
);
```

### Pattern 3: Mutate a graph schema

```typescript
import { GraphMutator } from 'alizarin';

const mutator = new GraphMutator(graph);
mutator.addStringNode(null, 'nickname', 'Nickname', 'n',
  'http://www.w3.org/2000/01/rdf-schema#Literal',
  'http://example.org/hasNickname');
const modified = mutator.apply();
```

`GraphMutator.apply()` runs the mutations through the core's graph mutator, so
the same mutations produce the same graph (ids included) on WASM, NAPI and
Python (`alizarin.GraphMutator`).

### Pattern 4: Switch to NAPI backend for performance

```typescript
import { setNapiModule } from 'alizarin';
setNapiModule(require('@alizarin/napi')); // also selects the 'napi' backend
// All subsequent ORM calls use native code
```

### Pattern 5: Edit a resource

```typescript
// Assign, then commit. Assignment is checked against the graph immediately
// (unknown/derived/semantic node, multi-valued node, unloaded nodegroup throw).
person.forename = 'Áine';             // plain strings set the current language
const names = await person.nicknames; // multi-valued: push / splice the list
names.push({ nicknames: 'Ani' });
const { upserted, removed } = person.$commit(); // tile delta; no I/O
// person.$discard() drops uncommitted edits.
```

There is **no** `setTileDataForNode`; edit by assignment (or the wrapper's
`checkEditable` / `applyEdits`, which the assignment sugar calls). Python's ORM
is the same with `place.title = ...`, `place.commit()` and `place.discard()`.

### Pattern 6: Lifecycle state

```typescript
import { resourceLifecycleState, transitionResourceLifecycle } from 'alizarin';
const state = resourceLifecycleState(resource, graph.resource_instance_lifecycle);
const { resource: record, event } = transitionResourceLifecycle(
  resource, graph.resource_instance_lifecycle, targetStateId);
```

See [Resource lifecycles](/docs/lifecycles) and [Resource layers](/docs/resource-layers)
(`composeResourceLayers`).

## Python Patterns

### Convert tiles to JSON tree

```python
import alizarin
tree = alizarin.tiles_to_json_tree(resource_json)
```

### Convert JSON tree back to tiles

```python
tiles = alizarin.json_tree_to_tiles(tree_json, resource_id, graph_id,
    from_camel=True, strict=False)
```

### Register and look up a graph

```python
graph_id = alizarin.register_graph(graph_json)
graph = alizarin.get_graph_json(graph_id)
model = alizarin.load_model(graph_id)   # ResourceModelWrapper
```

### Mutate a graph

```python
result = alizarin.apply_mutations_from_json(graph_json, mutations_json)
# or fluently, as in TypeScript:
mutator = alizarin.GraphMutator(graph)
```

### Lifecycle state

```python
state = alizarin.resource_lifecycle_state(json.dumps(resource), json.dumps(lifecycle))
result = alizarin.transition_resource_lifecycle(
    json.dumps(resource), json.dumps(lifecycle), target_state_id)
```

### Parse SKOS vocabularies

```python
# Add to the global RDM cache (returns the collection ids added)
ids = alizarin.add_from_skos_xml_to_global_cache(xml_string, base_uri)

# Or just parse; the parse functions live on the native module
from alizarin import alizarin as native
collection = native.parse_skos_xml_to_collection(xml_string, base_uri)
```

### Batch operations (parallel)

```python
tiles = alizarin.batch_trees_to_tiles(trees_json, graph_id, from_camel=True)
merged = alizarin.batch_merge_resources([batch1_json, batch2_json])  # list of JSON strings
```

## Graph Mutation CSV Format

Alizarin accepts graph mutations as CSV with a triple-like structure. This is the most portable way to define resource models programmatically.

```csv
action,subject,object,params.name,params.datatype,params.cardinality,params.ontology_class,params.parent_property
create_model,heritage_item,,Heritage Item,,,E18_Physical_Thing,
add_node,heritage_item,names,Names,semantic,n,E41_Appellation,P1_is_identified_by
add_node,names,name,Name,string,1,E41_Appellation,P1_is_identified_by
add_node,heritage_item,description,Description,string,1,E62_String,P3_has_note
```

**CSV columns:**
- `action`: `load_graph`, `create_model`, `create_branch`, `add_node`, `add_edge`, `add_nodegroup`, `add_card`, `add_widget`, `add_subgraph`, `update_subgraph`, `add_function`, `set_descriptor_function`, `set_descriptor_template`, `update_widget_config`, `rename_node`, `rename_card`, `rename_graph`, `realign_card_from_node`, `update_node`, `change_node_type`, `change_cardinality`, `coppice_subgraph`, `concept_change_collection`, `delete_node`, `delete_nodegroup`, `delete_card`, `delete_widget`, `delete_function`. Any unrecognised action is dispatched as an extension mutation by that name (e.g. `clm.reference_change_collection` from the CLM extension).
- `subject`: The parent alias (or model alias for `create_model`, graph ID for `load_graph`)
- `object`: The new element's alias
- `params.*`: Mutation-specific parameters (name, datatype, cardinality, ontology_class, parent_property, config, description, publication_id, alias_prefix, name_prefix). Supports **dot-notation** for nested values (e.g., `params.options.is_collector` becomes `{"options": {"is_collector": true}}`).

**Supported datatypes:** `string`, `number`, `date`, `boolean`, `concept`, `concept-list`, `resource-instance`, `resource-instance-list`, `geojson-feature-collection`, `url`, `edtf`, `file-list`, `domain-value`, `domain-value-list`, `semantic` (grouping node), `reference`

**Cardinality:** `1` (single value) or `n` (repeatable)

## Common Anti-Patterns to Avoid

1. **Don't parse Arches tiles manually.** Use `tiles_to_json_tree()` (Python) or `GraphManager.loadGraph()` (JS). The tile format is complex with nested nodegroups and provisional edits.

2. **Don't build graph JSON by hand.** Use the CSV mutation format or `GraphMutator`. Graphs have internal consistency requirements (nodegroup membership, edge integrity, card/widget linkage).

3. **Don't write custom SKOS parsers.** Use `parseSkosXml()` (JS) or `add_from_skos_xml_to_global_cache()` / the native module's `parse_skos_xml_to_collection()` (Python).

4. **Don't re-implement concept lookups.** Use the RDM system: `RDM.archesClient = archesClient` in JS (an `ArchesClient` instance, not the `client` namespace), or `add_from_skos_xml_to_global_cache()`/`resolve_labels()` in Python.

5. **Don't convert between camelCase and snake_case manually for Arches data.** The `from_camel` parameter in `json_tree_to_tiles()` handles this.

6. **Don't use raw HTTP to query Arches if Alizarin can do it.** `ArchesClientRemote` wraps the Arches REST API with proper pagination, error handling, and caching.

7. **Don't write tile data directly.** Assign to view-model fields and call `$commit()` (JS) / `commit()` (Python); the core checks, coerces and reruns derive functions. Older APIs such as `setTileDataForNode`, `toJsonFull`, `buildNodesForGraph` and `createPseudoValue` have been removed.

8. **Don't test for `undefined` in Alizarin output.** Absent values are `null` on every backend.

9. **Don't expect a reference to be loaded.** A resource-instance value is a stub until an attribute is read (or `retrieve()` called), and retrieving needs the target in the registry or reachable by the client. `getName()` is `null` for a graph with no descriptor function.
