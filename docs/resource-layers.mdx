---
title: Resource layers
description: Compose one resource across an ordered stack of layers (base + overlays)
---

A **resource layer** is a copy of a resource as it exists in one layer of an
ordered stack — a shared **base** plus **overlays** that override or extend it.
`composeResourceLayers` merges that stack, topmost layer winning, into a single
effective resource. The canonical use is a base dataset with per-context
overlays: *General* (base) → *Universe* → *Campaign*, where a campaign can
override an entity ("Hollowmere burned in campaign B") or add to it, without
duplicating the entity.

This is the in-memory form of what a storage-backed host does per request (e.g.
the ros-madair substrate's `hydrate_layers`, which reads each layer's tiles from a
store and then calls the **same** core primitives). The logic lives once in
`alizarin-core`; the bindings are thin wrappers.

## `composeResourceLayers`

Supply the same resource as it appears in each layer, **topmost-first** (the
highest-priority layer first). It returns `{ resource, warnings }`.

```typescript
// JS/TS (WASM) and Node (NAPI) — same signature; the backend is chosen for you
import { composeResourceLayers } from 'alizarin';

const { resource, warnings } = composeResourceLayers(
  [campaignResource, universeResource, generalResource], // topmost-first
  baseGraph,                                              // base model StaticGraph
  [],                                                     // overlay graphs (bottom-to-top); [] if none
  false,                                                  // strict
);
```

```python
# Python — JSON strings in, dict out
import alizarin, json

result = alizarin.compose_resource_layers(
    json.dumps([campaign, universe, general]),  # resources, topmost-first
    json.dumps(base_graph),                      # base model
    json.dumps([]),                              # overlay graphs, bottom-to-top
    False,                                       # strict
)
resource, warnings = result["resource"], result["warnings"]
```

## Merge semantics

| | Behaviour |
|---|---|
| **Ordering** | Resources are supplied **topmost-first**; the topmost layer that sets a value wins. |
| **Single-valued nodegroup** (cardinality 1) | Replaced **whole** by the topmost layer that sets it — there is **no** field-by-field inheritance from lower layers. A campaign that sets a `status` group replaces the base's entire `status` tile. |
| **Multi-valued nodegroup** (cardinality n) | **Accumulates** across layers — append-only. Layering can **add** members but never remove one; model "an alliance that ended" as a single-valued status or an event, not by deletion. |
| **Identical tiles** | A tile present unchanged in several layers (same tile id) is kept once. |
| **`strict`** | A cross-layer conflict on a single-valued group becomes an **error** instead of a warning. |

Identity (the resource id) is taken from the topmost layer. Resource ids are
stable across layers by design (always the default namespace), so an overlay can
override a resource it shares with the base, and a link resolves to the same
resource in any layer — see *layer-isolated tile ids* below.

## Model overlays

The `overlayGraphs` argument stacks **model** overlays under a
[`LayeredGraph`](/docs/architecture): composition runs against the merged
(overlaid) model, so an overlay may add or override nodegroups (e.g. a homebrew
tweak to a type), not just data. Overlays are listed **bottom-to-top** (the last
is topmost); `[]` composes against the base model alone.

## Layer-isolated tile ids

When you build each layer's resources from CSV, pass `uuidNamespace` so a layer's
derived **tile** ids don't collide with another layer's:

```typescript
import { buildResourcesFromBusinessCsv } from 'alizarin';

const campaignTiles = buildResourcesFromBusinessCsv(
  csv, graph, collections, 'en', true,
  'campaign-b',            // uuidNamespace — isolates this layer's tile ids
);
```

**Resource** ids always use the default namespace (so cross-layer lookup and
override work); only **tile** ids take the namespace. This is honoured identically
on WASM, NAPI and Python.

> **Scope.** `composeResourceLayers` composes resources **already in memory**. If
> your layers live in a store (Parquet/DuckDB, SQLite, a REST API), the read +
> compose belongs in your host/substrate, which calls the same core composer —
> keep storage out of the binding.
