The Python binding exposes `alizarin-core` functionality via PyO3. It provides tile/JSON conversion, graph mutation, RDM caching, SKOS parsing, extension support, resource layers and lifecycles — the same operations used by [AORM](https://github.com/flaxandteal/arches-orm/) and Arches-adjacent tooling — plus an ORM layer (`GraphManager`, `ResourceModelWrapper`, view models) mirroring the JS/TS one.

## Installation

```bash
pip install alizarin==2.0.0a147
```

Pin the exact version: the paused `2.0.0b*` releases sort above the current alphas, so `pip install --pre alizarin` would pick a stale beta.

Wheels are built against the stable ABI (`abi3`), so one wheel serves Python 3.9 and later, on Linux, macOS and Windows.

## Quick Example

```python
import alizarin
import json

# Register a graph (returns its graph_id)
with open("graph.json") as f:
    graph_json = f.read()
graph_id = alizarin.register_graph(graph_json)

# Convert tiles to a nested JSON tree (returns a dict)
with open("resource.json") as f:
    resource_json = f.read()
tree = alizarin.tiles_to_json_tree(resource_json)
print(tree)

# Convert back to tiles (json_tree_to_tiles takes a JSON string)
resource_id = tree["resourceinstanceid"]
tiles = alizarin.json_tree_to_tiles(
    json.dumps(tree), resource_id, graph_id,
    from_camel=True, strict=False
)
```

## ORM and editing

The ORM reads and edits resources as in JS/TS: values are edited by assignment (checked against the graph immediately) and applied with `commit()`, which returns the tile changes for you to persist.

```python
from alizarin.graph_manager import GraphManager
from alizarin.view_models import viewContext

gm = GraphManager()
gm.register_graph(graph_dict)
gm.register_resource(resource_dict)
viewContext.graphManager = gm

place = await gm.getResource(resource_id, lazy=False)   # inside an async function
place.title = "Baile"          # a plain string sets the current language's value
delta = place.commit()         # {"upserted": [...tiles], "removed": [...tile ids]}; or place.discard()
```

## Resource lifecycles

`resource_lifecycle_state(resource_json, lifecycle_json)` resolves a resource's state, and `transition_resource_lifecycle(resource_json, lifecycle_json, target, strict=True)` returns a transition record and event. Both take JSON strings; see [Resource lifecycles](/docs/lifecycles).

```python
state = alizarin.resource_lifecycle_state(json.dumps(resource), json.dumps(graph["resource_instance_lifecycle"]))
# {'status': 'state', 'state_id': 'f75bb034-…', 'is_initial': False, 'conflict': []}
```

## API Surface

### JSON Conversion

| Function | Description |
|----------|-------------|
| `tiles_to_json_tree(resource_json)` | Tiles to nested JSON tree |
| `build_tree_from_tiles(tiles_json, resource_id, graph_id)` | Pre-extracted tiles to tree |
| `batch_tiles_to_trees(...)` | Parallel batch tiles-to-tree conversion |
| `alizarin.alizarin.cards_to_json_tree(resource_json)` | Tiles to card-structured tree (in the compiled submodule, not re-exported) |
| `json_tree_to_tiles(tree_json, resource_id, graph_id, from_camel, strict, rdm_cache, id_key, scopes, tile_namespace)` | Tree back to tiles format |
| `batch_trees_to_tiles(trees, graph_id, from_camel, strict, ...)` | Parallel batch conversion |
| `resolve_labels_in_tree(...)` | Resolve human labels to concept UUIDs in a tree |

### Graph & Resource Registry

| Function | Description |
|----------|-------------|
| `register_graph(graph_json)` | Register a graph for lookups |
| `get_registered_graph_ids()` | List all registered graph IDs |
| `get_graph_json(graph_id)` | Retrieve registered graph as JSON |
| `get_graph_schema(graph_id)` | Retrieve registered graph schema |
| `merge_resources(resources_json)` | Merge a JSON array of resources (grouped by resourceinstanceid) |
| `batch_merge_resources(batches_json, recompute_descriptors, strict)` | Batch merge across multiple JSON batches |
| `streamed_merge_from_files(file_paths, chunk_size, ...)` | Memory-efficient stream-merge of resources from files |
| `ResourceRegistry` | Class: create and manage a resource registry |
| `compose_resource_layers(resources_json, base_graph_json, overlay_graphs_json, strict=False)` | Compose [resource layers](/docs/resource-layers) |
| `build_resources_from_business_csv(csv_data, graph_json, collections_json, ...)` | Build resource instances from business-data CSV |
| `resource_lifecycle_state(resource_json, lifecycle_json)` | Resolve a resource's [lifecycle](/docs/lifecycles) state |
| `transition_resource_lifecycle(resource_json, lifecycle_json, target, strict=True)` | Move a resource to another lifecycle state |

### Graph Mutations

All mutations are applied via JSON requests — see [Graph Mutations](/docs/mutations) for the full format.

| Function | Description |
|----------|-------------|
| `apply_mutations_from_json(graph_json, mutations_json)` | Apply mutations to a graph |
| `apply_mutations_create(...)` | Apply mutations that create a new graph |
| `apply_mutations_with_extensions(graph_json, mutations_json)` | Apply mutations including extension mutations |
| `register_extension_mutation(name, handler, conformance)` | Register a custom mutation handler |
| `has_extension_mutation(name)` | Check if an extension mutation is registered |
| `list_extension_mutations()` | List all registered extension mutations |
| `get_mutation_schema()` | Get mutation schema documentation |
| `generate_uuid_v5(group_type, key, group_id)` | Generate deterministic UUIDs |
| `build_graph_from_instructions(...)` | Build graph from instruction list |
| `build_graph_from_csv(...)` | Build graph from CSV definitions |

### RDM (Reference Data)

| Function | Description |
|----------|-------------|
| `set_global_rdm_cache(cache)` | Set global concept cache |
| `get_global_rdm_cache()` | Get global concept cache |
| `has_global_rdm_cache()` | Check if global cache exists |
| `clear_global_rdm_cache()` | Clear global cache |
| `add_collection_to_global_cache(...)` | Add a collection to the cache |
| `add_from_skos_xml_to_global_cache(...)` | Parse SKOS XML and add to cache |
| `add_from_skos_json_to_global_cache(...)` | Parse SKOS JSON and add to cache |
| `resolve_labels(...)` | Resolve concept labels to UUIDs |
| `get_needed_collections(...)` | Get collection IDs needed by a graph |
| `set_rdm_namespace(...)` / `get_rdm_namespace()` / `get_rdm_namespace_raw()` | Configure RDM namespace for UUID generation; the raw string is the base URI for SKOS XML |

### SKOS Vocabularies

These live in the compiled submodule (`from alizarin import alizarin as core; core.parse_skos_xml(...)`); they are not re-exported at the package top level.

| Function | Description |
|----------|-------------|
| `parse_skos_xml(xml, base_uri)` | Parse SKOS RDF/XML |
| `parse_skos_xml_to_collection(xml, base_uri)` | Parse to single collection object |
| `skos_collection_to_xml(collection_json, base_uri)` | Serialize collection to RDF/XML |
| `skos_collections_to_xml(collections_json, base_uri)` | Batch serialize collections |
