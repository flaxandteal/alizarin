The NAPI binding provides a native Node.js addon built with `napi-rs`. It serves as an alternative backend for the JS/TS ORM, offering better performance for large datasets and avoiding WASM overhead.

## Installation

```bash
npm install alizarin@alpha @alizarin/napi@alpha
```

`@alizarin/napi` is a backend for the `alizarin` ORM, so install both, from the 2.0 `alpha` tag (`latest` is an old line).

Pre-built binaries are included for:
- Linux x64
- macOS ARM64 (Apple Silicon)
- macOS x64
- Windows x64

Pre-built binaries are also available from [GitHub Releases](https://github.com/flaxandteal/alizarin/releases).

## Using as a JS/TS Backend

The NAPI backend is used through the same JS/TS ORM API. Switch backends with:

```typescript
import { setNapiModule, graphManager } from 'alizarin';

// Register the native addon; this also selects the NAPI backend
setNapiModule(require('@alizarin/napi'));

// Now all ORM operations use native code
const Person = await graphManager.loadGraph('Person');
const people = await Person.all(); // native speed
```

## Direct NAPI API

The NAPI module also exposes lower-level classes for direct use without the ORM layer:

### Classes

| Class | Description |
|-------|-------------|
| `NapiStaticGraph` | Parse and register graph definitions |
| `NapiStaticResourceRegistry` | Index and query resources with native performance |
| `NapiResourceModelWrapper` | Graph-level model wrapper: nodes, nodegroups, permissions |
| `NapiResourceInstanceWrapper` | Per-resource wrapper the ORM drives: tile loading, `checkEditable` / `applyEdits`, `toJson` / `toDisplayJson`, card serialisation |
| `NapiPrebuildExporter` | Export graphs and resources to a prebuild directory |
| `NapiRdmCache` | Reference data concept cache |

### NapiStaticGraph

```javascript
const graph = NapiStaticGraph.fromJsonString(graphJsonString);
console.log(graph.graphId, graph.name);
graph.register(); // register in global registry
```

### NapiStaticResourceRegistry

```javascript
const registry = new NapiStaticResourceRegistry();
registry.mergeFromResourcesJson(resourcesJson, true);

// Or load from business data bytes (Buffer)
const refs = registry.loadFromBusinessDataBytes(buffer, true);

// Build indexes for fast lookups
const index = registry.getValueToResourcesIndex(graph, nodeId, true);
const filtered = registry.getFilteredTileValues(
  graph, filterNodeId, filterValues, extractNodeId, true, null
);

// Direct access
const resource = registry.getFull(resourceId);
const summary = registry.getSummary(resourceId);
console.log(registry.length);
```

### Prebuild Import/Export

```javascript
// Import all graphs, collections, and resources from a prebuild directory
const result = importPrebuild('/path/to/prebuild', 'http://localhost:8000/');

// Export graphs to a directory
const exporter = new NapiPrebuildExporter();
exporter.exportAllGraphs('/path/to/output');
```

### Module Functions

| Function | Description |
|----------|-------------|
| `buildGraphFromCsvs(graphCsv, nodesCsv, collectionsCsv, rdmNamespace)` | Build graph definition from CSV strings |
| `buildBusinessDataFromCsv(csvData, graphJson, collectionsJson, ...)` | Build resource instances from CSV data |
| `composeResourceLayers(resourcesJson, baseGraphJson, overlayGraphsJson, strict?)` | Compose [resource layers](/docs/resource-layers) |
| `resourceLifecycleState(resourceJson, lifecycleJson)` | Resolve a resource's [lifecycle](/docs/lifecycles) state |
| `transitionResourceLifecycle(resourceJson, lifecycleJson, target, strict = true)` | Move a resource to another lifecycle state |
| `importPrebuild(prebuildDir, baseUri)` | Load graphs and resources from a prebuild directory |
| `tilesToTree(resourceJson)` / `cardsToTree(resourceJson)` / `batchTilesToTrees(resourcesJson, strict)` | Tiles to a node tree or card tree, against the registered graph the resource names, as WASM's (which take the graph). From `alizarin`, `tilesToTree(resourceJson, graph)` etc. route to the selected backend |
| `treeToTiles(treeJson, graph, fromCamel, strict, idKey?, randomIds?, tileNamespace?)` / `batchTreesToTiles(treesJson, graph, fromCamel, strict, idKeysJson?, randomIds?, resolveMarkers?, scopesJson?, tileNamespace?)` | Alias-keyed trees to tiled resources, as WASM's (same arguments, `graph` a `NapiStaticGraph`). Concept labels resolve against the global RDM cache when one is set. From `alizarin`, the same names route to the selected backend |
| `mergeResources(resourcesJson)` / `batchMergeResources(batchesJson, recomputeDescriptors?, strict?)` | Merge copies of a resource into one, or batches of resources per id, as WASM's |
| `compareNodes(a, b)` | Whether two nodes are the same apart from their ids, as WASM's `StaticNode.compare` |
| `constructStatic(kind, value)` / `resourcesFromBusinessDataJson(json)` | A static type (`"node"`, `"resource"`, …) built from an object, or a business data file's resources, as core builds them: what WASM's `new StaticNode(…)` and `StaticResource.fromBusinessDataJsonString` hold. From `alizarin`, `createStatic*` and `parseStaticResources` route here on NAPI |
| `summaryToMetadata(summary)` / `staticResourceFromSummary(summary)` | From a registry summary: its resource metadata, or a lightweight resource with no tiles (`tiles_loaded: false`), as core builds them (WASM: `summary.toMetadata()`, `StaticResource.fromSummary(summary)`) |
| `setRdmNamespace(namespace)` / `getRdmNamespace()` / `getRdmNamespaceRaw()` / `hasRdmNamespace()` / `clearRdmNamespace()` | The global RDM namespace (UUID or URL): deterministic IDs, and the base URI for SKOS XML. From `alizarin`, `setRdmNamespace` routes to the selected backend |
| `extensionCoerce(datatype, value, config)` | Call extension coercion |
| `extensionRenderDisplay(datatype, tileData, language)` | Call extension display renderer |

The module-level functions take JSON strings; through the ORM you would call `resourceLifecycleState` / `transitionResourceLifecycle` from `alizarin` instead, which accept objects and route to NAPI when it is the selected backend. As on every backend, results are core's JSON, with `null` (never `undefined`) for absent values.

## When to Use NAPI vs WASM

| | WASM | NAPI |
|-|------|------|
| **Runtime** | Browser + Node.js | Node.js only |
| **Install** | `npm install alizarin@alpha` (WASM binary ships in the package) | `npm install alizarin@alpha @alizarin/napi@alpha` |
| **Performance** | Good | Better (native) |
| **Memory** | Limited by WASM linear memory | Full system memory |
| **Dataset size** | Small to medium | Any size |
| **Use case** | Frontend, SSG, prototyping | ETL, batch processing, production pipelines |
