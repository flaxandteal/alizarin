`alizarin-core` is the pure Rust crate that powers all other bindings. Use it directly when you need maximum performance, want to embed Alizarin in a Rust application, or are building a new language binding.

## Installation

```toml
[dependencies]
alizarin-core = "=2.0.0-alpha.147"
```

The crate is published to [crates.io](https://crates.io/crates/alizarin-core). 2.0 prereleases are on the `alpha` line; pin the exact version with `=`, since a caret requirement would also accept the paused `2.0.0-beta.*` releases, which sort above the alphas.

## Quick Example

```rust
use alizarin_core::json_conversion::{tiles_to_tree, tree_to_tiles_with_options, ValidationMode};
use alizarin_core::graph::StaticGraph;

// Parse a graph definition
let graph: StaticGraph = serde_json::from_str(&graph_json)?;

// Convert tiles to a JSON tree (resource is a serde_json::Value)
let tree = tiles_to_tree(&resource, &graph)?;

// Convert back — returns (BusinessDataWrapper, Vec<ValidationDiagnostic>)
let (business_data, diagnostics) = tree_to_tiles_with_options(
    &tree,
    &graph,
    true,                    // strict
    None,                    // id_key
    false,                   // from_camel
    false,                   // random_ids
    false,                   // has_extension_handlers
    None,                    // extension_registry
    ValidationMode::Collect, // validation mode
)?;
```

## Key Types

| Type | Module | Description |
|------|--------|-------------|
| `StaticGraph` | `graph` | Complete graph definition with nodes, edges, cards |
| `StaticNode` | `graph` | A single node in the graph |
| `StaticResource` | `graph` | Resource instance with tiles |
| `StaticResourceRegistry` | `graph` | Indexed collection of resources |
| `PrebuildLoader` | `loader` | Load graphs and resources from a prebuild directory |
| `RdmCache` | `rdm_cache` | Reference data concept cache |
| `Interner` | `interner` | String interning for memory-efficient UUID handling |
| `NodeConfig` | `node_config` | Per-node configuration and coercion settings |
| `ExtensionTypeRegistry` | `extension_type_registry` | Custom datatype handler registration |

## Module Overview

The crate is organised into ~39 top-level public modules. The most commonly used:

- **`graph`** — Core data structures (`StaticGraph`, `StaticNode`, `StaticEdge`, etc.)
- **`json_conversion`** — Tile/tree bidirectional conversion
- **`graph_mutator`** — Programmatic graph schema modification
- **`csv_model_loader`** / **`csv_business_data_loader`** — CSV-based graph and data loading
- **`rdm_cache`** / **`rdm_namespace`** — Reference data management
- **`skos`** — SKOS RDF/XML parsing and serialization
- **`type_coercion`** — Multi-phase value coercion across Arches datatypes
- **`registry`** — Global graph registry (graphs by id, for functions that look them up)
- **`resource_edit`** — `ResourceEdit` / `EditOp`: the edits behind every binding's assign-and-commit
- **`loader`** — Prebuild directory loading
- **`label_resolution`** — Resolve human labels to concept UUIDs
- **`extension_type_registry`** — Plugin system for custom datatypes

## Lifecycles

```rust
use alizarin_core::graph::{transition, EffectiveState};

let lifecycle = graph.lifecycle()?;   // compiled once, cached on the graph
if let EffectiveState::State { id, .. } = lifecycle.effective_state(&resource.resourceinstance) { /* … */ }
let (record, event) = transition(&resource.resourceinstance, lifecycle, target, true)?;
```

`StaticResourceMetadata` carries the stored state as `resource_instance_lifecycle_state_id`, and `lifecycle_state_conflict` when composed layers disagreed. See [Resource lifecycles](/docs/lifecycles).
