Some datatypes aren't in the core — they're provided by **extensions** that
register a handler over the [Extension ABI](/docs/extension-abi). The view models
work exactly like the built-in ones once the handler is registered.

To use them, install and import the package — it self-registers on `wasmReady`:

```typescript
import 'alizarin';
import '@alizarin/clm';       // registers the `reference` datatype
import '@alizarin/filelist';  // registers the `file-list` datatype
```

The docs harness does exactly this, so the demos below run live.

## reference (CLM)

The `reference` datatype (Controlled List Manager) is a controlled-list value —
like `concept`, but its labels can be carried inline on the value rather than
resolved from a separate collection. `ReferenceValueViewModel` stringifies to the
label in the current language. The node config names a `controlledList`.

## file-list (images & files)

The `file-list` datatype wraps an array of files. `FileListViewModel` **extends
`Array`**, each item a `FileItemViewModel` exposing `.name`, `.url`, `.fileType`,
`.size`. For images, read `.url` straight into an `<img>` tag.
