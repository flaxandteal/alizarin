Alizarin has two temporal datatypes: `date` for exact calendar dates, and `edtf`
(Extended Date/Time Format) for fuzzy, partial, or interval dates.

## date

`DateViewModel` wraps an Arches `date`. **It resolves to a `Date` object**, which
is *not* a valid React child on its own — format it before rendering
(`new Date(d).toISOString().slice(0, 10)`, `d.toLocaleDateString()`, etc.). This
is the single most common footgun with the typed view models: a raw `Date` (or
`Number`) put straight into JSX throws *"Objects are not valid as a React child"*.

## edtf

`EDTFViewModel` wraps an `edtf` value — the [Extended Date/Time
Format](https://www.loc.gov/standards/datetime/), which expresses uncertainty and
intervals that a plain `date` cannot: `1984?` (uncertain year), `1985-04-12/1985-06`
(an interval), `19XX` (an unspecified decade). Use it for historical records where
precision varies.
